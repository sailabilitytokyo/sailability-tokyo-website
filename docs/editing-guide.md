# サイトの更新手順

よくある更新作業の手順です。**AI に頼む場合**は「依頼の例」をそのまま使えます。**自分で直す場合**は各手順の「ファイル」を GitHub の画面で編集します。

どちらの方法でも、変更は「プルリクエスト（PR）」として作られ、次の流れで公開されます。

1. PR ができると、自動チェック（CI）と**プレビュー URL の発行**が始まる（数分）
2. PR の画面に表示される Cloudflare のプレビュー URL を開いて、見た目を確認する
3. CI が緑（成功）になっていれば「Merge」ボタンを押す → 数分で本番サイトに反映

## 1. セーリング体験会の日程を追加する

**依頼の例**
> 10月のセーリング体験会の日程を追加して。10/11(日)と10/25(日)、どちらも13:00-15:00、豊洲。

**ファイル**: `src/data/schedule.yaml` の末尾に追加

```yaml
- date: 2026-10-11
  start: '13:00'
  end: '15:00'
  kind: experience
  place: toyosu
```

- 申込締切は自動で「開催日の2日前」になります。変える場合は `deadline: 2026-10-08` を追加。
- 過去の日程は自動で表示されなくなるので、消さなくて大丈夫です。
- トップページ・体験会ページの日程表と、Google 検索向けのイベント情報に自動で反映されます。
- 必要なら「お知らせ」も書きます（下記 2.）。日程表だけで十分なら不要です。

### 中止・満員にする

該当の日程に `status: cancelled`（中止）または `status: full`（満員）を追加します。

> 10/11の体験会は荒天のため中止にして。お知らせも出して。

### 外部イベントに出展する

```yaml
- date: 2026-11-03
  kind: event
  place: yumenoshima
  title: 夢の島マリーナ ○○フェスでハンザ乗船体験会
```

新しい場所の場合は、先に `src/data/site.yaml` の `places` に場所を追加します。

## 3. 小学生ヨット教室の募集を開始・終了する（前期・後期の切り替え）

教室は前期・後期制です。**ページの URL（`/junior-sailing-courses`）は変えず、期ごとに変わる部分だけを書き換えます。**

**依頼の例**
> 2027年前期の小学生ヨット教室の募集を開始して。募集期間は3/1〜3/20、日程は（…）、定員20名、参加費20,000円、申込フォームは https://forms.gle/xxxx
> 小学生ヨット教室の募集を締め切って。

**ファイル**: `src/content/pages/ja/junior-sailing-courses.md`（期ごとに変える項目はファイル先頭のコメントに書いてあります）

| 時期 | 変えるところ |
| --- | --- |
| 募集開始 | `summary`・`tags` の期の表記（例: 2027年前期 募集中）、本文冒頭のお知らせ、「募集概要」の表、「日程」、`cta` の `#` を外してフォームの URL を書く |
| 募集締切〜開講中 | `summary`・`tags`・本文冒頭を「開講中・受付終了」に、`cta` を `#` で無効化 |
| 期の終了後 | `summary`・`tags`・本文冒頭を「次回の募集は決まり次第ご案内」に |

- 必要に応じて「お知らせ」も書きます（下記 2.）。
- 期によって変わらない部分（教室の特徴・安全体制・保護者の声など）はそのままにします。

## 5. 写真を追加する

写真は必ず変換してから追加します（位置情報の削除とサイズ縮小のため）。

1. Google フォトなどから写真をダウンロード
2. AI に依頼:
   > ~/Downloads/photos にある写真をサイト用に変換して、セーリング体験会ページの一番上に使って。写真の説明は「豊洲の水面を進むハンザ」。
3. 自分でやる場合: `npm run photos -- ~/Downloads/photos` を実行すると `src/assets/photos/` に保存される。ページの frontmatter に以下を追加:

```yaml
image: ../../../assets/photos/ファイル名.jpg
imageAlt: 豊洲の水面を進むハンザ
```

**注意**: 子どもの顔がはっきり写った写真は、保護者の掲載同意が取れているものだけにしてください（公開リポジトリの履歴に残るため、後から完全に消すのが難しい）。

## 6. スポンサーを追加する

**依頼の例**
> スポンサーに「株式会社○○（https://example.com）」を追加して。ロゴは ~/Downloads/logo.png

**ファイル**: `src/data/site.yaml` の `sponsors`

```yaml
  - name: 株式会社○○
    url: https://example.com
    logo: sponsors/example.png   # src/assets/ からの場所。ロゴがなければこの行は不要（名前が表示される）
```

ロゴの変換: `npm run photos -- --out src/assets/sponsors ~/Downloads/logo.png`

## 7. 翻訳を追加する（英語・中国語）

**依頼の例**
> セーリング体験会のページの英語版と簡体字中国語版を作って。

- `src/content/pages/en/sailing-experience.md`、`src/content/pages/zh-hans/sailing-experience.md` のように、言語のフォルダに同じファイル名で作る。
- 翻訳があるページには、自動で言語切り替えが表示される。
- トップページの翻訳（`home.md`）がある言語では、お知らせ一覧 `/en/news` なども生成される。
- 画面の固定文言（「予約する」など）の翻訳は `src/i18n/ui.ts` に追加する。
- 場所名などデータの翻訳は `site.yaml` / `schedule.yaml` で `ja:` / `en:` のように書き分けられる。

## 8. トップページの文言を変える

**ファイル**: `src/content/pages/ja/home.md` の frontmatter

| 項目 | 表示される場所 |
| --- | --- |
| `hero` | 一番上の大きな見出し・説明・ボタン・タグ。写真を用意したら `background`（背景）や `photo`（右側の写真）を追加 |
| `highlights` | 「はじめてでも、心配はいりません」の4項目（`icon` は `src/icons/` のファイル名） |
| `intro` | 団体紹介の見出し（本文は `---` の下の Markdown） |
| `membership` | 会員募集の帯 |

活動紹介のカードは各ページ（`sailing-experience.md` など）の `title` / `summary` / `tags` / `image` から自動で作られます。

**注意（YAML の書き方）**: カンマ `,` やコロン `:` を含む文字は `'...'` で囲みます。例: `{ label: '参加費 1,500円', icon: japanese-yen }`

## 困ったとき

- **CI が赤（失敗）になった**: PR の画面の「Details」からエラーを確認し、AI に「CI が失敗したので直して」と依頼する。エラー文をそのまま渡すと早い。
- **監視の Issue が届いた**: Issue の本文を AI に渡して「原因を調べて直して」と依頼する。
- **間違えて公開してしまった**: GitHub の PR 画面の「Revert」ボタンで元に戻せる。
